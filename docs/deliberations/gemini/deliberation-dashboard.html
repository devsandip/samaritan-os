1. Self-Organizing the Deliberation Protocol

Live Agent Postures at This Beat

How Each LLM Approached the Problem

All three models read the exact same brief (`scratch-pad.md`), yet each approached the problem with a distinct engineering lens, uncovered different ground-truth facts, and had blind spots that the other two caught.

Claude Product & Ecosystem Architect

Mental model: Contract-first platform design & developer-folder synthesis
How Claude Approached It
  • Created the governance rules first: Wrote PROTOCOL.md with `D1`-`D10` decision IDs, `/STATUS.md` signalling, and the alphabetical tie-break rule so the three models wouldn't talk past each other.
  • Scanned the wider `~/Developer` portfolio: Discovered `MailMCP`, `clawhub/scrask-bot`, `healthAI`, and `job_tracker` early and shared those facts with Codex and Gemini in `messages-to-peers.md`.
  • Found native Claude Code HTTP hooks: Identified `Notification` matchers (`permission_prompt`, `idle_prompt`, `agent_needs_input`) and `Stop`/`SessionEnd` hooks that POST directly to Samaritan.
  • Investigated billing mechanics (`C2`): Uncovered the tension between April 2026 third-party harness restrictions and the Oct 7, 2026 Max monthly API credits policy.
Blind Spots Caught by Peers
  • Relied on a third-party guide claiming Hermes approvals were "off by default" (Codex proved `smart` is default in official docs).
  • Assumed Gemini Spark was still US-only (Codex found the July 29, 2026 Google India Pro rollout).
  • Proposed an "auto-approve after N minutes unless I object" tier in `D9` (Codex and Gemini pushed back: silence must never approve a write).

Codex (ChatGPT) Systems & Security Auditor

Mental model: Distributed systems correctness, failure modes & authority boundaries
How Codex Approached It
  • Audited source code against README claims: Verified line-by-line that `TelegramDelivery.flush()` (`src/delivery/index.ts:158`) had zero callers and `withTimeout()` (`src/run-layer/index.ts:145`) only stopped waiting via `Promise.race`.
  • Proved the exact SQLite trigger boundary: Showed that triggers in `migrations.ts` only prevent `UPDATE/DELETE` on `action_item_events`; in-process TS capabilities can still bypass the registry unless isolated.
  • Enforced strict human approval authority: Caught that `src/api/server.ts` trusted request-supplied `actor: "sandip"` and blocked giving MCP clients an approval tool.
  • Verified primary schemas: Pulled Oura's V2 OpenAPI 1.42 JSON schema directly to prove `PublicDailyStress` is a daily aggregate, not a real-time mental-stress stream.
Blind Spots Caught by Peers
  • Proposed a 2-day OpenClaw vs SDK benchmark trial before building Phase 1 (Claude and Gemini pushed back: `WorkerAdapter` gives swappability without delaying Week 1).
  • Proposed 10 new SQLite tables including separate `questions`, `approvals`, and `outbox` tables (Gemini and Claude pushed back: that creates a second inbox alongside `action_items` and `delivery_queue`).

Gemini Workflow & Schema Minimalist

Mental model: Day-in-the-life UX mapping, schema consolidation & code bug hunting
How Gemini Approached It
  • Mapped all 11 daily beats end-to-end: Translated every bullet in `scratch-pad.md` (06:45 wake to 18:00 job scout and Friday WBR) into Samaritan `manifest.yaml` triggers, render layouts (`card`, `form`, `document`, `diff`), and execution modes.
  • Found the UTC date bug (`G2`): Spotted that `dailyNotePath()` in `src/execution/adapters/obsidian.ts` computes dates in UTC, causing notes written after 00:00 IST to file into the wrong day.
  • Designed the Ask/Delegate Command Bar: Proposed unifying Recall RAG ("Ask") and Cowork task submission ("Delegate") in one top bar across views.
  • Compressed the SQLite schema to 4 tables: Pushed back on Codex's 10-table model so task questions and approvals stay inside `action_items` with nullable `task_id`, `run_id`, and `payload_hash`.
Blind Spots Caught by Peers
  • Included `samaritan_act` in Round 1's MCP tool list (Codex and Claude rightly rejected it: an injected LLM session could approve its own staged action).
  • Proposed a 15-minute auto-regenerated `BRAIN_INDEX.md` containing live calendar/decisions (Claude and Codex pushed back: keep the pointer file static so personal/work data isn't dumped into every repo).
  • Proposed a `source_cursors` table before Codex pointed out `sync_cursors` already exists in Migration 1.
